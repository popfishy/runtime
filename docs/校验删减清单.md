# 校验删减清单

**日期**：2026-09-20
**目的**：去掉锁死"v1 固定剧本"和场地几何的校验，便于修改任务流程做实物测试。
**原则**：只保留与实物飞行中飞机、人员安全相关的校验。

改动统计：7 个文件，新增 10 行 / 删除 383 行。

---

## 一、已删除

### 1. `validate_scenario_package()` 整个函数（最大一块）

**原位置**：`src/uav_bt_runtime/package.py:295-493`（调用点 `:225`）
**已改为**：`load_mission_package` 中直接调用 `_validate_reviewed_scene_coordinates`（现 `package.py:218`）

原函数把 v1 剧本写死，删掉的内容：

| 原校验 | 说明 |
|---|---|
| GroupA 动作顺序必须精确等于那 10 个 Action | 增删/调序动作即被拒 |
| GroupB 动作顺序必须精确等于那 6 个 Action | 同上 |
| prepare / coverage1 / recovery / coverage2 / hold 的分配 UAV 集合必须精确等于预期 | 改分配即被拒 |
| fault 计划数量 == `planned_fault_count`、候选必须初始 active、不得含 Leader | 改故障配置即被拒 |
| coverage 必须有且仅有 1 条 Leader 路径、≥3 航点、follower 必须 `formation_follow: true` | 改编队方式即被拒 |
| segment2 起点必须等于 segment1 终点 | 改分段即被拒 |
| **segment1 不得进上区、segment2 不得回下区、必须由下往上推进** | 改航点走向即被拒 |
| recovery / hold 目标点必须等于 route2 端点 | 改目标点即被拒 |
| fault-exit 必须 ≥2 航点 | 改退出航线即被拒 |
| strike 必须恰好 2 架、必须 active、目标集合必须等于 world 的两个 target | 改打击编组即被拒 |

**连带删除**（只被该函数调用）：`_actions_by_id`、`_plan_for_action`、`_require_exact_assignments`。

**影响**：改动作顺序 / 分配 / 航点走向 / 分段逻辑全部放行。
失去"手改 plans.json 后仍符合 v1 剧本"的把关，**但不影响飞行安全**——发往飞机的指令安全校验在 `tcp_transport.py` 里另有一套，未动。

### 2. 场地大小约束

| 位置 | 原校验 |
|---|---|
| `package.py:38` `FlightArea` | `2*margin` 不得吃光场地 |
| `spatial.py:21` `FieldConfig` | 同上 |

**影响**：场地区间与 margin 随便填。保留 `max > min`、宽高为正、margin ≥ 0（数据结构自身合法性）。

### 3. `CoordinateMapper` 自动缩放

**位置**：`spatial.py:82` `from_packages`
**原行为**：任一坐标落进 margin 内就整体缩放（`scale` 变 0.979 之类）。
**已改为**：固定 `scale=1.0`、`offset_x=offset_y=0`，按原始坐标绘制。

**影响**：仅影响 `visual_simulation`（可视化 / 无头仿真）。实机 TCP 路径完全不引用 `spatial` 模块。越界坐标会画到画布外。

### 4. 跨组联合校验的三条

**位置**：`package.py:259` `validate_joint_packages`

- `target_config_version` 必须相等 —— 已删
- 两组 `world.json` **逐字节相同** —— 已删（此前 17 个联合测试全红的元凶）
- UAV 总数 ≥ 30 —— 已删（含 `minimum_uavs` 参数）

**影响**：两组可各用各的 world / 目标点，小规模包也能联合仿真。

### 5. 恢复数量的配置记账

| 位置 | 原校验 |
|---|---|
| `config.py` `build_mission_context` | `planned_recovery_count <= planned_fault_count` |
| `config.py` `build_mission_context` | reserve 数 >= `planned_recovery_count` |
| `models.py` `MissionContext` | `planned_recovery_count <= planned_fault_count` |

**影响**：配置写错不再在加载期报错，改为跑到 recovery 动作时由 `actions.py` 报出。

## 二、明确保留（未改动）

- **哈希与路径**：`require_reviewed`、`file_hashes` 精确覆盖、SHA-256 校验、路径不得逃逸包目录、重复引用检查
- **指令下发**（`tcp_transport.py` 全部）：仅支持 A/B 组、host 非空、端口 1..65535、超时 > 0、批非空、单消息必须同 mission/Action/Group/命令类型、**单指令不得含重复 UAV ID**、**Group B 的 ATTACK/RETURN 必须恰好 B01+B02**、JSON ≤ 64 KiB、回包 `group_id`/版本/类型校验、COMPLETED 必须精确列出每个被指挥的 UAV
- **机型与人员安全**（`models.py`）：Leader/Reserve 互斥、faulted 不可 available、roster 四类 ID 不重复且互斥、`expires_at > issued_at`、`timeout_s > 0`、assignment key 与 `robot_id` 匹配、spec/state 一对一同组、**能力匹配 capability**、跨组引用禁止
- **跨组**：`mission_id` 相同、peer 版本互指、**两组 UAV ID 不得重复**
- **引用完整性**：Action → 未知 plan / 他组 plan；plan → 未知 target_id；plan_id 跨文件唯一
- **坐标必须是数字**（`_validate_reviewed_scene_coordinates`）：JSON 里写成字符串不会静默下发到飞机
- **行为树解析**（`bt/parser.py`）与**运行时动作**（`actions.py`）全部
