# 多无人机集群容错自愈联合任务方案

## 一、任务背景

本项目计划在湖南大学国家大学科技园约 `100 m × 150 m` 的室外场地开展多无人机实飞实验。实验使用不少于 30 架四旋翼无人机，分为两个无人机集群，每个集群由独立地面站进行控制。

实验主要研究多无人机集群在任务执行过程中出现成员损失后，如何通过任务重分配、重规划，使集群继续完成后续任务。项目只在任务规划与组织层面体现“容错与自愈”。

本方案在设计准备、区域覆盖侦查、模拟打击三个主要阶段。打击完成后，两组剩余有效无人机直接返航。

## 二、实验目标

实验拟验证以下能力：

1. 不少于 30 架无人机能够以两个集群的形式参与联合任务；
2. 侦查集群能够以编队方式执行区域覆盖任务；
3. 当侦查编队中的n架无人机退出任务后，整体侦查任务不会立即失败；
4. 备用无人机能够接替故障成员的位置和任务；
5. 恢复后的侦查编队能够继续完成剩余区域覆盖；
6. 侦查结果能够触发另一集群执行模拟打击；
7. 打击完成后，两个集群的剩余有效无人机能够安全返回指定区域；
8. 通过完整任务过程体现多无人机集群在任务层面的容错、自愈与任务连续性。

## 三、无人机组织形式

### 1. Group A：侦查集群

Group A 主要承担区域覆盖侦查任务，包括：

- 建立侦查编队；
- 执行第一段区域覆盖；
- 进行一次预设的模拟故障；
- 启用备用无人机；
- 恢复编队或恢复点阵；
- 执行第二段区域覆盖；
- 形成并发送目标信息；
- 等待打击完成后返航。

Group A 中设置固定领航无人机、普通侦查成员、至少一架备用无人机，以及一架预先指定的模拟故障无人机。模拟故障对象不选择领航无人机。

### 2. Group B：打击集群

Group B 主要承担模拟打击任务，包括：

- 建立打击待命编队；
- 在侦查阶段保持待命；
- 接收 Group A 的侦查结果和目标信息；
- 派出主打击成员或打击编队；
- 在主打击任务失败时启用备用成员；
- 打击完成后返航。

Group B 第一版不主动注入第二次故障，以降低 30 架以上无人机联合实飞的调试难度和现场风险。

## 四、总体任务流程

```text
┌──────────────────────────────────────────────────┐
│ Group A 区域                                     │
│ A-Start → A-Staging → Coverage-Segment-1         │
│                         ↓                        │
│              Fault-Hover / Fault-Landing         │
│                         ↓                        │
│              Recovery Area / Join Point          │
│                         ↓                        │
│                 Coverage-Segment-2               │
│                         ↓                        │
│                      A-Hold                      │
│                                                  │
│              中央安全缓冲区                      │
│                                                  │
│ Group B 区域                                     │
│ B-Start → B-Staging → Strike Corridor → Target   │
│                                                  │
│ 任务结束：A-Return、B-Return                     │
└──────────────────────────────────────────────────┘
```

总体流程如下：

> 人工起飞与悬停准备 → 两组集结和编队 → Group A 执行第一段区域覆盖 → 模拟故障 → 备用无人机接替 → Group A 执行第二段区域覆盖 → 发送目标信息 → Group B 执行模拟打击 → 两组返航 → 人工降落。

正常起飞和最终降落由人工完成，不纳入上层任务流程。任务从全部计划无人机稳定悬停后开始，到两个集群返回指定区域并稳定悬停后结束。

## 五、准备阶段

两个地面站分别控制本组无人机完成人工起飞。所有参与无人机到达预先设置的初始悬停位置后，进行基本飞行状态和定位状态检查。

准备完成后：

- Group A 前往侦查集结区，建立侦查编队；
- Group B 前往打击待命区，建立待命编队或固定点阵；
- 两个集群均确认准备完成后，Group A 开始区域覆盖侦查；
- 任意一个集群准备失败时，联合任务不启动。

无人机连接、RTK 定位、电量、飞控状态和编队稳定性等检查由底层飞行系统完成。上层任务系统只接收“准备成功”或“准备失败”的结果，避免在行为树中重复处理大量底层状态。

## 六、区域覆盖侦查阶段

### 1. 区域覆盖方式

Group A 的无人机以一个或多个简单编队执行区域覆盖任务。覆盖区域和覆盖航迹在实验前完成设计和审核，不在实飞过程中在线生成复杂航迹。

为便于模拟故障和后续恢复，完整覆盖任务划分为前后两个连续任务段：

- 第一段覆盖：侦查编队完成区域的一部分覆盖；
- 中间安全点：编队进入稳定悬停状态，用于模拟故障；
- 第二段覆盖：备用无人机接替后，恢复编队继续完成剩余区域。

这种设计能够避免复杂的实时路径重规划，同时保留“故障后继续完成未完成区域”的任务含义。

### 2. 模拟故障

侦查编队完成第一段覆盖后，在预设安全位置悬停。上层任务系统在这一固定阶段自动向预先指定的n架非领航无人机发送模拟损毁指令。

该无人机按照底层安全流程缓慢降落，并退出后续任务。其他侦查成员在故障机下降期间保持安全状态。

底层飞行系统在执行模拟故障前负责确认定位状态、下降区域和周边飞行安全；安全条件不满足时，应拒绝执行模拟故障。

### 3. 任务恢复

故障机退出后，侦查集群启用预先设置的备用无人机。

如果底层支持成员动态加入编队，备用无人机进入故障成员原有编队位置；如果暂时不支持动态重编队，则让剩余无人机和备用无人机进入预先设置的固定恢复点阵。

恢复完成后，Group A 继续执行第二段覆盖任务。第二段覆盖完成即表示侦查阶段完成。

这一过程体现了任务级自愈：

> 单机退出任务后，集群通过备用成员接替恢复任务组织，并继续完成剩余侦查，而不是整体终止或从头开始任务。

### 4. 侦查结果

侦查完成后，Group A 形成目标信息并发送给 Group B。(不需要发送，全局坐标是知道的)

第一版实验可以使用预先设置的目标坐标，不强制依赖实时视觉识别。后续如接入实际感知设备，可将目标信息替换为真实侦查结果，而不改变整体任务流程。

## 七、模拟打击阶段

Group B 在收到 Group A 的侦查完成和目标信息后，派出主打击成员或简单打击编队前往目标区域。

模拟打击可采用以下方式之一：

- 到达目标点后稳定悬停；
- 到达目标点后亮灯；
- 后续条件允许时增加投弹装置。

无论采用哪种方式，上层任务逻辑保持不变。具体悬停、灯光或投弹控制均由底层完成。

如果主打击任务失败，可由预先设置的备用打击成员重新执行任务。第一版不在打击阶段主动制造第二次故障，只验证备用打击分支能够处理实际任务失败或底层拒绝。

主打击或备用打击成功后，打击阶段结束。

## 八、返航收尾

打击任务完成后：

- Group A 的剩余有效无人机返回 A 组指定返回区域；
- Group B 的剩余有效无人机返回 B 组指定返回区域；
- 已经受控降落的模拟故障机不再参与返航；
- 两组到达后保持稳定悬停；
- 上层联合任务结束；
- 两个地面站分别由人工完成最终降落。

取消封控阶段后，可以缩短任务时长，降低高温条件下的续航压力，同时保留准备、侦查、故障恢复、打击和返航的完整任务链路。

## 九、容错与自愈体现

本方案通过以下过程体现项目主题：

1. 侦查任务在单机退出后仍保持可继续执行；
2. 故障机能够被识别并从任务成员中移除；
3. 备用无人机能够接替故障成员；
4. 编队或固定恢复点阵能够重新建立；
5. 区域覆盖任务能够继续完成；
6. 侦查结果仍能触发后续打击；
7. 整个联合任务最终能够完成并返航。

与单纯展示n架无人机降落相比，本方案的重点是展示故障发生后，集群任务如何恢复并继续推进。

## 十、控制复杂度简化原则

为保证方案能够在有限调试时间内落地，上层行为树只负责：

- 任务阶段顺序；
- 两组任务分工；
- 模拟故障触发；
- 备用无人机启用；
- 主任务失败后的备用分支；
- 打击完成后的返航决策。

以下内容由底层飞行系统自行检查和执行：

- GPS + RTK 定位质量；
- 飞控模式、电量和基础健康状态；
- 区域覆盖航迹跟踪；
- 编队保持；
- 无人机是否到达和悬停是否稳定；
- 故障下降区域是否安全；
- 备用无人机加入编队的具体路径；
- 固定恢复点阵的飞行控制；
- 避障和防碰撞；
- 返航到点判断。

两个地面站之间只需要交换四类信息：(有待商榷)

1. 两组是否准备完成；
2. 侦查是否完成以及目标信息；
3. 打击是否完成；
4. 联合任务是否中止。

这一简化能够避免把大量飞行状态和安全条件转换成行为树节点，从而降低编程、联调和现场排故难度。


## 十一、实施前需要明确的事项

为了形成正式场地图和实验流程，还需要与相关成员确认：

1. Group A 和 Group B 的准确无人机数量；
2. 两组无人机 ID、领航机、普通成员和备用成员；
3. Group A 使用一个侦查编队还是多个小编队；
4. 侦查区域以及两段覆盖航迹；
5. 故障悬停点、故障降落点和恢复点阵；
6. 底层是否能够执行编队区域覆盖并返回任务成功或失败；
7. 底层是否支持受控降落和备用成员加入；
8. 两个地面站之间传递阶段信息的方式；
9. 目标坐标来源和模拟打击方式；
10. 两组返回区域及返航顺序；
11. GPS + RTK 统一原点和实际定位精度；
12. 场地安全边界、飞行高度、任务时长和人工接管流程。


## 十二、结论

本方案以“准备—区域覆盖侦查—模拟打击—返航”为任务主线，通过侦查编队成员受控失效、备用无人机接替和剩余覆盖任务继续执行，体现多无人机集群的任务级容错与自愈。

方案不依赖复杂的在线路径重规划，也不要求行为树直接处理大量飞行状态。上层只进行阶段调度和异常分支决策，底层负责飞行控制和安全自检，能够在保留研究主题的同时有效控制实现难度，适合作为后续实物实验的总体任务方案提交审阅。
